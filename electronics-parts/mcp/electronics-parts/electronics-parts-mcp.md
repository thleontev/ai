# MCP-сервер Electronics Parts

`electronics-parts` - единый MCP-сервер OpenCode для поиска и подбора электронных компонентов.
Он работает с DigiKey, Mouser, LCSC (официальный API и публичный поиск без API) и официальным Components API JLCPCB, а также с публичной выдачей ChipDip, Промэлектроника, Elitan, Berelcom, ДКО Электронщик и Platan.

## Возможности

| Источник | Что делает MCP | Требование к доступу |
| --- | --- | --- |
| DigiKey | Параметрический поиск по каталогу, цены, наличие, даташиты | Приложение DigiKey Product Information API |
| Mouser | Поиск по ключевым словам и MPN, цены, наличие, даташиты | Ключ Mouser Search API |
| LCSC | Официальный поиск, розничное наличие и ценовые уровни | Одобренный LCSC B2B API и whitelist IP-адреса |
| LCSC (публичный) | Поиск без API по тому же публичному backend, что использует сайт lcsc.com: точный MPN/C-код → C-код, цены, остатки, даташит; keyword → та же выдача «Verified Third-party Channels», что показывает сайт | Ничего не требуется; без ключей, cookies и внутренних страниц |
| JLCPCB | Наличие для сборки, цены и характеристики по LCSC C-коду | Одобренное приложение JLCPCB Components API |
| ChipDip | Один явно запрошенный поиск по публичной HTML-странице | Разрешение на автоматизированный доступ к поиску |
| Промэлектроника | Один явно запрошенный поиск по публичной HTML-странице | Разрешение на автоматизированный доступ к поиску |
| Elitan | Один явно запрошенный поиск по публичной JSON-выдаче поиска; с `ELITAN_COOKIE` — персональные партии, цены и скидки | Разрешение на автоматизированный доступ к поиску; для персональных данных — своя браузерная сессия в `ELITAN_COOKIE` |
| Berelcom | Один явно запрошенный поиск по публичной HTML-странице и разделы каталога (shop.berelcom.ru) | Разрешение на автоматизированный доступ к поиску |
| ДКО Электронщик | Один явно запрошенный поиск по публичной HTML-странице (www.electronshik.ru) | Разрешение на автоматизированный доступ к поиску |
| Platan | Один явно запрошенный поиск по публичной HTML-странице (www.platan.ru, windows-1251) | Разрешение на автоматизированный доступ к поиску |

Официальный Components API JLCPCB работает с кодами LCSC вида `C12345`: сначала найдите компонент в LCSC, затем запросите у JLCPCB данные о наличии для PCBA.

## Безопасность

- Не добавляйте ключи в `opencode.jsonc`, исходный код, Git или сообщения чата.
- Храните ключи только в переменных окружения Windows текущего пользователя.
- Если ключ отсутствует, пустой или остался неразрешённой строкой вида `{env:...}`, MCP останавливается до любого HTTP-запроса и возвращает сообщение о недостающих ключах. API поставщика не вызывается.
- HTML-поиск ChipDip, Промэлектроника, Berelcom, ДКО Электронщик и Platan, а также JSON-поиск Elitan не являются API. Используйте их только при письменном разрешении поставщика на автоматизированный доступ к публичной странице поиска.
- Публичные инструменты LCSC (`search_lcsc_public_components`, `get_lcsc_public_component_details`) работают без API и ключей через публичные backend-ресурсы сайта lcsc.com; для массовых или коммерческих запросов используйте официальный LCSC API.
- HTML/JSON-инструменты делают ровно один запрос к странице поиска по явному запросу пользователя; карточки товаров догружаются только при `include_product_details: true` или отдельными инструментами деталей, не обходят каталог, ограничены десятью результатами и ждут не менее 5 секунд между запросами к одному сайту.
- При `HTTP 403`, `HTTP 429` или CAPTCHA MCP прекращает работу без повторного запроса и не пытается обходить защиту сайта.
- `ELITAN_COOKIE` — ваша собственная сессия Elitan. Не передавайте её другим, не добавляйте в Git и не выводите в чат. При истечении сессии обновите cookie.
- Наличие и цены являются оперативными данными и могут измениться до подтверждения заказа.
- Текущая версия MCP не создаёт заказы. Она только ищет и читает данные о компонентах.

## Предварительные условия

- Имя MCP-сервера в конфигурации: `electronics-parts`.
- Сервер можно настроить в проектном или глобальном конфиге OpenCode; при запуске внутри проекта проектный конфиг имеет приоритет.
- В `command` указан **абсолютный путь** `C:\Program Files\nodejs\node.exe`: приложение OpenCode не видит `node` в PATH (`uv_spawn 'node' ENOENT`), поэтому просто `"node"` не работает.
- Для работы сервера требуется Node.js 20 или новее и каталог `mcp/electronics-parts` этого репозитория с `server.mjs`, `package.json` и установленными зависимостями.
- Можно настроить ключи не для всех поставщиков. Инструмент без ключа сообщит, что требуется настроить, но остальные поставщики продолжат работать.

## Добавление ключей API в Windows

Запустите следующие команды в PowerShell. Подставляйте реальные значения только на своём компьютере.

```powershell
[Environment]::SetEnvironmentVariable("DIGIKEY_CLIENT_ID", "ваш-digikey-client-id", "User")
[Environment]::SetEnvironmentVariable("DIGIKEY_CLIENT_SECRET", "ваш-digikey-client-secret", "User")

[Environment]::SetEnvironmentVariable("MOUSER_API_KEY", "ваш-mouser-api-key", "User")

[Environment]::SetEnvironmentVariable("LCSC_API_KEY", "ваш-lcsc-api-key", "User")
[Environment]::SetEnvironmentVariable("LCSC_API_SECRET", "ваш-lcsc-api-secret", "User")

[Environment]::SetEnvironmentVariable("JLCPCB_APP_ID", "ваш-jlcpcb-app-id", "User")
[Environment]::SetEnvironmentVariable("JLCPCB_ACCESS_KEY", "ваш-jlcpcb-access-key", "User")
[Environment]::SetEnvironmentVariable("JLCPCB_SECRET_KEY", "ваш-jlcpcb-secret-key", "User")
```

Проверка наличия переменных без вывода самих ключей:

```powershell
$names = @(
  "DIGIKEY_CLIENT_ID", "DIGIKEY_CLIENT_SECRET", "MOUSER_API_KEY",
  "LCSC_API_KEY", "LCSC_API_SECRET",
  "JLCPCB_APP_ID", "JLCPCB_ACCESS_KEY", "JLCPCB_SECRET_KEY",
  "ELITAN_COOKIE"
)

foreach ($name in $names) {
  "${name}: $([bool][Environment]::GetEnvironmentVariable($name, 'User'))"
}
```

После создания или изменения переменных полностью закройте и заново запустите OpenCode. Конфигурация MCP и переменные окружения читаются только при запуске OpenCode.

## Настройка DigiKey

1. Создайте учётную запись или войдите на <https://developer.digikey.com/>.
2. Создайте приложение Product Information API.
3. Скопируйте `Client ID` и `Client Secret`.
4. Задайте `DIGIKEY_CLIENT_ID` и `DIGIKEY_CLIENT_SECRET` командами выше.
5. Перезапустите OpenCode.

MCP автоматически получает OAuth-токены. Никогда не добавляйте `Client Secret` в конфигурацию MCP.

## Настройка Mouser

1. Запросите ключ Mouser Search API на <https://www.mouser.com/api-search/>.
2. Задайте `MOUSER_API_KEY`.
3. Перезапустите OpenCode.

Публичный API Mouser не предоставляет универсальный структурированный параметрический фильтр. Указывайте электрические требования и в поисковой строке, и в `filters`, затем обязательно проверяйте возвращённые характеристики и даташит.

## Настройка LCSC

1. Создайте учётную запись на <https://www.lcsc.com/>.
2. Подайте заявку на B2B API: <https://www.lcsc.com/agent/partner>.
3. Передайте LCSC требуемые сведения, включая публичный IP-адрес исходящего интернет-соединения.
4. Дождитесь одобрения API и добавления IP-адреса в whitelist.
5. Задайте `LCSC_API_KEY` и `LCSC_API_SECRET`.
6. Перезапустите OpenCode.

MCP использует официальный LCSC `KeywordSearch` API. Обычный лимит LCSC составляет 200 запросов в минуту и 1000 поисков в сутки, если поставщик не одобрил больший лимит. При ошибке MCP возвращает текст вида `LCSC API error <код>: <сообщение>` без повторных попыток. Частые случаи:

| Ошибка LCSC | Причина | Что делать |
| --- | --- | --- |
| Код/сообщение об отказе в доступе к API | Доступ к API не включён | Дождаться одобрения или обратиться в поддержку LCSC |
| `403` / сообщение о запрете IP | IP-адрес не разрешён | Попросить LCSC добавить публичный IP в whitelist |
| Ошибка подписи запроса | Неверные ключ/секрет или алгоритм подписи | Проверить выданные ключ и секрет (алгоритм меняется переменной `LCSC_SIGNATURE_ALGORITHM`, по умолчанию `sha256`) |

## Публичный поиск LCSC без API

Инструменты `search_lcsc_public_components` и `get_lcsc_public_component_details` работают без ключей и без официального API: они обращаются к тем же публичным ресурсам, которые сам сайт lcsc.com использует в браузере.

- **Точный MPN или C-код** (`AP63203WU-7`, `C780769`) возвращает полные данные: C-код, MPN, производителя, категорию, корпус, упаковку, ценовые уровни, остатки по складам, даташит и ссылку на карточку.
- **Произвольный keyword** основной backend отдаёт бренды/категории со счётчиками; если он не вернул строк товаров, сервер дополнительно делает тот же второй запрос, что делает страница поиска lcsc.com, и возвращает панель «Verified Third-party Channels» (`third_party_items` — с C-кодами, ценами, остатками и сроками). Это поведение ровно соответствует сайту. Второй запрос отключается параметром `include_third_party: false`.
- Если сайт для запроса перенаправляет на страницу категории (например `ESP32-WROOM-32`), сервер не обходит каталог, а возвращает `available_brands`/`available_catalogs` и готовую ссылку `category_url` на ту же категорию.
- `get_lcsc_public_component_details` читает встроенные структурированные данные публичной карточки `https://www.lcsc.com/product-detail/C<код>.html` (MPN, параметры, цена, наличие). Разрешаются только C-коды — произвольный MPN по карточке без API не ищется.

Ограничения:

- Это не официальный API: маршруты могут измениться или быть ограничены без предупреждения. Для массовых и коммерческих запросов используйте официальные инструменты `search_lcsc_components`/`get_lcsc_component_details`.
- Один явный запрос пользователя на вызов; не более двух backend-запросов (как делает сама страница поиска); пауза не менее 5 секунд между запросами к LCSC; при `HTTP 429` или CAPTCHA повторных попыток нет.
- Cookies, авторизация, корзина, `product-detail-v2` и внутренние страницы не используются.

## Настройка JLCPCB

1. Войдите на <https://api.jlcpcb.com/>.
2. Подайте заявку на API-доступ и создайте приложение с доступом к Components API.
3. Скопируйте `App ID`, `Access Key` и `Secret Key`.
4. Задайте `JLCPCB_APP_ID`, `JLCPCB_ACCESS_KEY` и `JLCPCB_SECRET_KEY`.
5. Перезапустите OpenCode.

MCP использует подписанный официальный JLCPCB Components API только для поиска данных о компонентах и просмотра библиотеки. Создание заказов на платы, трафареты и сборку не реализовано.

## Настройка Elitan (опциональная авторизация через cookie)

Elitan скрывает точные партии, цены и скидки от неавторизованных посетителей. Вход по логину/паролю защищён графической CAPTCHA, поэтому MCP **не может** входить автоматически и не обходит CAPTCHA. Вместо этого MCP использует вашу браузерную сессию: вы входите на elitan.ru один раз в браузере, копируете cookie и передаёте его серверу через переменную окружения `ELITAN_COOKIE`.

Cookie — это ваша собственная сессия, поэтому использование личного кабинета не нарушает политику «не обходим защиту», но требует согласия Elitan на автоматизированный доступ с этой сессией.

### Как извлечь cookie из браузера

**Вариант 1 — через DevTools (рекомендуется, работает во всех браузерах):**

1. Откройте браузер (Chrome/Edge/Firefox) и войдите на <https://www.elitan.ru/> — убедитесь, что вы авторизованы (виден Личный кабинет).
2. Нажмите `F12` (DevTools) → вкладка **Application** (Chrome/Edge) или **Storage** (Firefox).
3. В левом списке выберите **Cookies** → `https://www.elitan.ru`.
4. Скопируйте из таблицы все cookie для домена `elitan.ru` в формате `имя=значение`, разделяя точкой с запятой и пробелом: `cookie1=value1; cookie2=value2; ...`.
5. Задайте переменную окружения `ELITAN_COOKIE` (команда ниже) и перезапустите OpenCode.

**Вариант 2 — через консоль DevTools (копирует все cookie одной командой):**

1. Войдите на elitan.ru, откройте DevTools (`F12`).
2. На вкладке **Console** вставьте:
   ```js
   copy(document.cookie)
   ```
   Это скопирует строку `name1=value1; name2=value2; ...` в буфер обмена.
3. Вставьте её в переменную окружения.

**Вариант 3 — расширение для экспорта cookie (например, «EditThisCookie» или «Cookie-Editor»):**

1. Установите расширение, войдите на elitan.ru.
2. Откройте расширение → Export → скопируйте cookie для домена elitan.ru.
3. Приведите к формату `name1=value1; name2=value2; ...` (только `name` и `value`, без прочих полей).

### Как задать ELITAN_COOKIE

```powershell
[Environment]::SetEnvironmentVariable("ELITAN_COOKIE", "cookie1=value1; cookie2=value2; ...", "User")
```

Проверка (без вывода значения):

```powershell
"ELITAN_COOKIE: $([bool][Environment]::GetEnvironmentVariable('ELITAN_COOKIE', 'User'))"
```

После этого полностью закройте и заново запустите OpenCode. В выдаче `search_elitan_components` появится флаг `authenticated: true`, а запросы к elitan.ru будут содержать ваш cookie. Если cookie устарел (сессия истекла), сервер вернёт ответ без персональных данных — обновите cookie и перезапустите OpenCode.

Без cookie инструмент `get_elitan_component_details` сообщит, что партии скрыты за авторизацией; с `ELITAN_COOKIE` он вернёт полную карточку через собственные JSON-эндпоинты Elitan (без парсинга HTML): анализ рынка по складам (источник, срок, наличие, оптовая цена, признак минимальной цены), минимальную цену, доступное количество, ставку НДС и все заказываемые партии — по каждой: наличие, срок («сегодня», «от N дн.»), минимальный заказ, кратность упаковки, риски логистики и резерва, ценовые уровни «от N шт». Партии отсортированы по сроку доставки (0 дн. — первые), и для каждой рассчитана цена на заданное количество `unit_price_rub_for_quantity` (параметр `quantity`, по умолчанию 3 шт) по её ценовым уровням. Входной параметр — `partname_full` вида `MPN@ТИКЕР` (его возвращает поиск в поле `partname_full`, например `AO4407A@ALPHAOMEGA`); `product_url` — опционально для справки.

## Инструменты MCP

| Инструмент | Назначение |
| --- | --- |
| `search_electronics_components` | Единый поиск в DigiKey, Mouser и LCSC (официальный API) с отдельными результатами по поставщикам; публичные источники подключаются только явным перечислением в `distributors` |
| `search_digikey_components` | Параметрический поиск DigiKey по полям каталога |
| `get_digikey_component_details` | Полные данные DigiKey по точному номеру компонента |
| `search_mouser_components` | Поиск Mouser по ключевым словам или MPN производителя |
| `get_mouser_component_details` | Данные Mouser по точному номеру Mouser |
| `search_lcsc_components` | Поиск официального каталога LCSC, розничное наличие и цены |
| `get_lcsc_component_details` | Данные LCSC по C-коду или MPN производителя |
| `search_lcsc_public_components` | Поиск LCSC без API: тот же публичный search-backend сайта lcsc.com (точный MPN/C-код → C-код, цены, остатки, даташит; keyword → панель «Verified Third-party Channels» сайта). Один явный запрос, пауза 5 с, без ключей, cookies, обхода каталога и повторов; останавливается на CAPTCHA/429 |
| `get_lcsc_public_component_details` | Публичная карточка lcsc.com по C-коду (встроенные структурированные данные): MPN, производитель, категория, параметры, цена, наличие. Без ключей; только C-коды |
| `get_jlcpcb_component_details` | Наличие для сборки и характеристики JLCPCB по LCSC C-кодам |
| `list_jlcpcb_component_library` | Постраничный просмотр официальной библиотеки JLCPCB |
| `search_chipdip_components` | Один ограниченный поиск в публичной HTML-выдаче ChipDip по явному запросу пользователя |
| `search_promelec_components` | Один ограниченный поиск в публичной HTML-выдаче Промэлектроника по явному запросу пользователя; опция `include_product_details` догружает карточки |
| `get_promelec_component_details` | Карточка Промэлектроника по URL: склады, наличие, минимальный заказ, срок, ценовые уровни |
| `search_elitan_components` | Один ограниченный поиск в публичной JSON-выдаче Elitan (elitan.ru) по явному запросу пользователя; опция `include_product_details` догружает карточки |
| `get_elitan_component_details` | Карточка Elitan через собственные JSON-эндпоинты (`index_json.php?script=bignote` + `/ajax/get_analysis_json`) по `partname_full` (например `ESP32-S3-WROOM-1-N8@ESPRESSYST`): анализ рынка, доступное количество, минимальная цена, все партии (ценовые уровни, мин. заказ, срок, склад, кратность упаковки, риски); полные партии — только с `ELITAN_COOKIE` |
| `search_berelcom_components` | Один ограниченный поиск в публичной HTML-выдаче Berelcom (shop.berelcom.ru) по явному запросу пользователя |
| `search_electronshik_components` | Один ограниченный поиск в публичной HTML-выдаче ДКО Электронщик (www.electronshik.ru) по явному запросу пользователя; опция `include_product_details` догружает карточки |
| `get_electronshik_component_details` | Карточка ДКО Электронщик по URL: наличие, минимум, цена «от», срок отгрузки |
| `search_platan_components` | Один ограниченный поиск в публичной HTML-выдаче Platan (www.platan.ru) по явному запросу пользователя |
| `search_elitan_parametric` | Параметрический подбор Elitan (`/param/getdata`): категория `el_type` или описание `component_type` + фильтры (`body_type`, `resistance` (Ом точкой, 4 знака, напр. `4700.0000`), `tolerance` (буквенный код, напр. `F` = ±1%), `tkr`, `mfg`, `term_delay`...). Без `el_type`/`component_type` — список категорий; без `filters` — доступные значения фильтров со счётчиками. Если точная комбинация даёт 0 результатов (`count_search=0`) — `exact_match` с `total_matches=0` и авто-повтор с уменьшенным числом параметров (до 4 попыток). Вызывается только по требованию; Elitan ограничивает нагрузку — не запускать несколько запросов подряд |
| `search_chipdip_parametric` | Параметрический поиск ChipDip по страницам каталога (`?p.0=<бренд>&x.<id>=<значение>&moq=<диапазон>`); категория — slug или `component_type`. Без `filters` — список доступных фильтров с подписями. Пустая комбинация (0 из N) — `exact_match` и авто-уменьшение параметров (до 4 попыток). Только по требованию |
| `search_promelec_parametric` | Параметрический поиск Промэлектроника по группам каталога (`brand=<ID>`, `body3=<ID>`, `instock=1`); категория — путь или `component_type`. Без `filters` — ID производителей/корпусов. Пустая комбинация (404 или 0 позиций) — `exact_match` и авто-уменьшение параметров (до 4 попыток). Только по требованию |
| `search_electronshik_parametric` | Параметрический поиск ДКО Электронщик (`kpd_d*` — числовые, `kpd_t*` — списки); категория — slug или `component_type`. Фильтр применяется POST-запросом, результат читается по короткому URL (tinyurl). Пустой результат («Найдено: 0») — `exact_match` и авто-уменьшение параметров (до 4 попыток). Только по требованию |
| `search_platan_parametric` | Параметрический поиск Platan (`p_<тип>_<слот>_<id>=<значение>`; несколько параметров комбинируются в одном запросе, кириллица в windows-1251); категория — `category_id` или `component_type`. Без `filters` — список параметров категории (`kind`: `list`/`range`). Если точная комбинация параметров даёт 0 результатов (сайт отвечает HTTP 404 на пустую выдачу), возвращается `exact_match` с `total_matches=0` и выполняется автоматический повтор с уменьшенным числом параметров (по одному с конца, до 4 попыток). Только по требованию |
| `search_berelcom_parametric` | Параметрический поиск Berelcom с локальной фильтрацией: раздел каталога (карта `/map/`; `category` — ID/путь/URL или `component_type`), до 3 страниц по 100 позиций (`?count=100`), фильтры применяются клиентски к названиям/описаниям карточек с сопоставлением единиц RU/EN (мкФ/mkF, В/V, кОм/kOhm и т.п.). Строгих совпадений нет — ранжированные кандидаты с `unmet_requirements`. Только по требованию |
| `search_digikey_parametric` | Параметрический поиск DigiKey через API: первый запрос снимает серверные параметрические фильтры, второй повторяет поиск с `ParameterFilterRequest` (для узких запросов); иначе — клиентское ранжирование. Только по требованию |
| `search_mouser_parametric` | Параметрический поиск Mouser через API: фильтры применяются клиентски к результатам keyword-запроса (API не поддерживает серверные фильтры). Только по требованию |
| `search_lcsc_parametric` | Параметрический поиск LCSC через API: фильтры применяются клиентски к результатам keyword-запроса. Только по требованию |

## Параметрический поиск (по требованию)

Параметрические инструменты **никогда не вызываются единым поиском** `search_electronics_components` — только явным обращением к ним. Общая схема работы: сначала вызовите инструмент без фильтров, чтобы получить доступные категории/параметры и их значения, затем повторите с `filters`.

```json
{
  "el_type": "smres",
  "filters": { "body_type": "2512", "resistance": "0.0100", "tolerance": "F±1%" },
  "limit": 10
}
```

```text
Найди в Элитане чип-резисторы 2512 10 Ом ±1%
```

Особенности источников:

- **Elitan**: значения `resistance`/`tkr` — в омах с точкой и 4 знаками (`4700.0000` = 4.7 кОм), `tolerance` — буквенные коды из списков (`F` = ±1%), `mfg` — название изготовителя, `term_delay` — максимальный срок отгрузки в днях. Ответ `/param/getdata` может быть очень большим (сотни позиций с подробными партиями), поэтому возвращаются только первые позиции в компактном виде. Для первого кандидата цена самой быстрой партии догружается автоматически (`price_rub`/`quickest_batch`). Если точная комбинация даёт 0 позиций (`count_search=0`) — возвращается `exact_match` с `total_matches=0` и выполняется авто-повтор с меньшим числом параметров (по одному с конца, до 4 попыток). **Elitan намеренно ограничивает нагрузку**: сервер может отвечать с задержками или возвращать `Fatal error` (лимит выполнения PHP) на тяжёлые параметрические запросы. Поэтому: интервал между запросами к Elitan увеличен до 8 секунд, на временный сбой допускается ровно один повтор, и не рекомендуется запускать несколько параметрических запросов Elitan подряд. При сбое повторите запрос позже.
- **ChipDip**: значения параметров `x.<id>` закодированы сайтом — фильтры можно задавать по названию и подписи: `{"Ёмкость": "10 мкФ"}` или `{"Бренд": "Murata"}` — коды подставятся автоматически (см. `resolved_filters`); ёмкости сопоставляются численно (мкФ/нФ/пФ/µF). `moq` — диапазоны мин. заказа (1..5). При пустом `filters` возвращаются доступные фильтры с подписями. Если комбинация даёт 0 позиций — `exact_match` с `total_matches=0` и авто-повтор с меньшим числом параметров (`applied_filters`/`dropped_filters`/`attempts`).
- **Промэлектроника**: `brand` и `body3` — числовые ID из `available_filters` (несколько брендов через `;`). Пустая комбинация (сайт отвечает 404 или 0 позиций) — `exact_match` и авто-уменьшение параметров (по одному с конца, до 4 попыток).
- **ДКО Электронщик**: фильтры применяются POST-запросом, отфильтрованный список приходит прямо в ответе (короткий URL tinyurl не отдаёт отфильтрованную выдачу). Числовые фильтры (`kpd_d*`, `kpd_rd*`) — диапазон в базовых единицах: ёмкость в фарадах («10 мкФ»/«0.00001»), напряжение в вольтах («50 В»); списковые (`kpd_t*`) — значения как на сайте («0805»). Пагинация отфильтрованных результатов не поддерживается (первый экран, до 40 строк). Пустой результат — `exact_match` и авто-уменьшение параметров (до 4 попыток).
- **Platan**: несколько параметров комбинируются в одном запросе (например `filters: {"Емкость (значение), мкФ": "470", "Диаметр корпуса D,мм": "6.3"}` для категории 91549); несколько значений одного параметра — через `;` (OR); параметры `kind=range` (например «Емкость (диапазон), мкФ») задаются диапазоном «10-100» (от-до); кириллица в значениях кодируется в windows-1251. Названия параметров можно брать из `available_filters` (заголовок или имя `p_<тип>_<слот>_<id>`). Если точная комбинация параметров не даёт результатов (сайт отвечает HTTP 404 на пустую выдачу), инструмент возвращает `exact_match: {total_matches: 0, ...}` и автоматически уменьшает число параметров (по одному с конца, до 4 попыток), возвращая ослабленные результаты в `candidates` с `applied_filters`/`dropped_filters`.
- **Berelcom**: параметрического поиска на сайте нет (только сортировка/пагинация) — инструмент `search_berelcom_parametric` сам парсит раздел каталога (карта `/map/`, до 3 страниц по 100 позиций) и фильтрует локально по тексту названий и описаний. Единицы сопоставляются в русском и английском написании (мкФ/mkF, В/V, кОм/kOhm и т.п.); «Доступно» — остаток, показанный в разделе; RoHS определяется по тексту карточки. Строгих совпадений нет — возвращаются ранжированные кандидаты с `unmet_requirements`. Для разделов с тысячами позиций результат неполный (обзор первых страниц).
- **DigiKey/Mouser/LCSC**: используются официальные API. Серверную параметрику поддерживает только DigiKey (двухэтапный запрос, работает для узких/точных запросов); Mouser и LCSC — клиентская фильтрация по полям ответа.

### Автоматический выбор категории

Категорию можно не указывать: передайте свободное описание в `component_type` (например «чип резистор 0805», «керамический конденсатор SMD», «полевой транзистор MOSFET») — сервер сопоставит его с известными категориями сайта (для Berelcom — по живой карте каталога `/map/`, для остальных — по статическому реестру) и подставит `el_type`/`category`/`category_id` сам. Если категория не распознана — инструмент вернёт список известных категорий (поля `available_categories`/`categories`/`available_sections`).

```json
{
  "component_type": "чип резистор 0805",
  "filters": { "resistance": "4700.0000", "tolerance": "F" },
  "limit": 10
}
```

## Ограничение размера ответа (контекст модели)

Все ответы инструментов автоматически ограничиваются ~40 000 символов (порядка 10k токенов), чтобы не переполнять контекст модели:

- если ответ больше лимита, сначала удаляются громоздкие поля (`price_breaks`, `stock_batches`, `card_details`, `market_analysis`, `datasheet_urls` и т.п.);
- затем сокращается число кандидатов (с пометкой в `note`);
- в крайнем случае остаётся один кандидат; в ответ добавляется поле `note` с пояснением.

Для получения остальных позиций уменьшите `limit`, уточните фильтры или используйте пагинацию (`page`).

## Параллельная обработка источников (мультиагентность)

`search_electronics_components` запрашивает все выбранные источники **одновременно** (`Promise.all`): DigiKey, Mouser, LCSC и публичные сайты идут в один заход, падение или медленность одного источника не блокирует остальные (ошибка попадает в `sources[].error`). Общее время ответа определяется самым медленным источником.

- `timeout_seconds` (по умолчанию 90) — дедлайн на каждый источник: не успевший возвращается как ошибка таймаута, а остальные результаты отдаются сразу.
- Ограничение сайта соблюдается: пауза 5 с (8 с для Elitan) действует только между запросами к одному и тому же сайту, разные сайты не ждут друг друга.
- Для последовательных вызовов по одному источнику используйте отдельные инструменты `search_*_components`.

## Отображаемые названия поставщиков

Во всех ответах MCP (поле `distributor` кандидатов и блоков источников единого поиска, тексты ошибок, поле `source` параметрического поиска) используются отображаемые названия:

| Внутренний ключ (параметр `distributors`, имена инструментов) | Отображаемое название в ответах |
| --- | --- |
| `promelec` / `search_promelec_components` | Промэлектроника |
| `electronshik` / `search_electronshik_components` | ДКО Электронщик |
| `chipdip` / `search_chipdip_components` | Чип и Дип |
| `elitan` / `search_elitan_components` | Элитан |
| `berelcom` / `search_berelcom_components` | Берелком |
| `platan` / `search_platan_components` | Платан |

Маппинг выполняет сервер (`displayDistributorName`), поэтому во входящих параметрах по-прежнему указываются внутренние ключи (`promelec`, `chipdip`, `elitan`, `berelcom`, `platan`, `electronshik`) — менять их не нужно. Международные поставщики (DigiKey, Mouser, LCSC, JLCPCB) возвращаются под своими названиями без изменений.

## Поля заказа в результатах

Все кандидаты (кроме DigiKey/Mouser/LCSC, где их нет в API) содержат нормализованные поля для заказа:

| Поле | Смысл | Где заполняется |
| --- | --- | --- |
| `available_quantity` / `quantity_available` | Наличие на момент поиска | все публичные источники |
| `minimum_order_quantity` | Минимальный объём заказа в шт. | ChipDip, Platan, Berelcom, Elitan |
| `lead_time` | Срок поставки заказа (например «2-3 р/дня», «от 4 дн.», «со склада», «поставка 17 августа») | ChipDip, Platan, Berelcom, Elitan, ДКО Электронщик |
| `price_breaks` / `price_rub` | Ценовые уровни «от N шт» или цена «от» | все публичные источники |
| `restock_date` / `in_stock_now` | Планируемая дата поступления / наличие сейчас | Platan |
| `minimum_term_delay_days` | Минимальный срок отгрузки в днях по партиям | Elitan |
| `product_details.warehouses` | Полная карточка: по складам наличие, минимальный заказ, срок, ценовые уровни | Промэлектроника (карточка) |
| `product_details.minimum_order_quantity` | Минимальный заказ из карточки | ДКО Электронщик (карточка) |

Карточки товаров догружаются только по явному запросу: флаг `include_product_details: true` в `search_promelec_components`, `search_electronshik_components` и едином поиске (догружает карточки первых 5 кандидатов, по одному запросу на кандидата с тем же интервалом 5 с), либо отдельными инструментами `get_promelec_component_details` / `get_electronshik_component_details` по URL из результатов поиска.

Ограничение: Промэлектроника на странице поиска показывает только наличие, «Под заказ» и цену «от» — минимальная партия и срок видны лишь в карточке товара. Используйте `include_product_details: true` или `get_promelec_component_details` для получения полных данных по складам: наличие, минимальный заказ, срок, ценовые уровни.

## Пример: ограниченный HTML-поиск ChipDip, Промэлектроника, Berelcom, ДКО Электронщик, Platan или Elitan

Используйте только при разрешении поставщика на автоматизированный доступ к странице поиска:

```json
{
  "query": "AP63203WU-7",
  "limit": 3
}
```

Передайте объект в `search_chipdip_components`, `search_promelec_components`, `search_berelcom_components`, `search_electronshik_components`, `search_platan_components` или `search_elitan_components`.

- Выполняется только одна загрузка публичной страницы поиска.
- Карточки товаров, внутренние endpoint-ы, корзина и авторизация не используются.
- Для ChipDip ответ может содержать предложения с доставкой, а не наличие на локальном складе.
- Для Промэлектроника поле `price_from_rub` означает отображаемую цену «от» и может зависеть от количества.
- Для Elitan поле `quantity_available` агрегирует склады поставщиков-партнёров, а не является наличием на едином складе; цены в рублях.
- Для Berelcom поле `available_quantity` соответствует строке «Доступно N шт» на странице поиска и может отличаться от фактического остатка на складе.
- Для ДКО Электронщик наличие и цена могут зависеть от региона и состояния входа на сайт.
- Для Platan сайт отдаёт страницы в кодировке windows-1251; поле `restock_date` — планируемая дата поступления, `in_stock_now` — есть ли товар сейчас на складе.
- Если сайт вернул CAPTCHA, `HTTP 403` или `HTTP 429`, повторного запроса не будет.

## Пример: поиск LCSC и проверка сборки JLCPCB

1. Найдите компонент в LCSC и получите его `C`-код.

```json
{
  "query": "STM32F103C8T6",
  "in_stock_only": true,
  "currency": "USD",
  "limit": 10
}
```

Передайте этот объект инструменту `search_lcsc_components`.

2. Проверьте, доступен ли выбранный C-код для сборки в JLCPCB.

```json
{
  "lcsc_codes": ["C17976"]
}
```

Передайте этот объект инструменту `get_jlcpcb_component_details`.

Не считайте розничное наличие LCSC и наличие JLCPCB для сборки одним и тем же запасом. Это разные складские пулы; для решения по PCBA используйте ответ JLCPCB.

## Рекомендуемый процесс подбора

1. Укажите обязательные электрические параметры, корпус, температурный диапазон, сертификацию и требуемое количество.
2. Вызовите `search_electronics_components` или поиск конкретного поставщика.
3. Проверьте точные характеристики и даташиты лучших кандидатов.
4. Сравните ценовые уровни, срок поставки, статус жизненного цикла и наличие для требуемого количества.
5. Для сборки JLCPCB найдите LCSC C-код и вызовите `get_jlcpcb_component_details` до выбора компонента в BOM.
6. Перед объявлением компонента прямой заменой проверьте посадочное место, land pattern и дерейтинг в даташите производителя.

## Устранение проблем

| Симптом | Решение |
| --- | --- |
| Инструмент сообщает, что ключ не настроен | Задайте указанную переменную пользователя Windows и перезапустите OpenCode |
| OpenCode по-прежнему показывает старые MCP-серверы | Полностью перезапустите OpenCode: конфигурация не перечитывается на лету |
| MCP в статусе `failed`, ошибка `uv_spawn 'node' ENOENT` | Приложение не видит `node` в PATH. Укажите в `command` абсолютный путь `C:\\Program Files\\nodejs\\node.exe` и перезапустите OpenCode |
| MCP в статусе `failed` после синхронизации папки проекта | Проектный `opencode.jsonc` может содержать путь другой машины. Поправьте `command` и `cwd` на локальные пути этой машины |
| Инструменты LCSC без API вернули пустой `items` и `category_url` | Публичный backend перенаправил запрос на категорию (как делает сайт). Перейдите по `category_url` или используйте официальный API-инструмент |
| LCSC возвращает ошибку доступа или IP | Проверьте одобрение API и whitelist публичного IP-адреса |
| JLCPCB возвращает ошибку авторизации | Убедитесь, что приложение имеет Components API access и заданы все три переменные JLCPCB |
| Поиск нашёл близкий, но не точный аналог | Проверьте `unmet_requirements`, точные параметры каталога и даташит производителя |
| ChipDip, Промэлектроника, Berelcom, ДКО Электронщик, Platan или Elitan вернул `HTTP 403`, `HTTP 429` либо CAPTCHA | MCP не повторяет запрос. Уточните у поставщика разрешение, whitelist IP или официальный read-only фид; не меняйте User-Agent для обхода защиты |

## Установка на другом компьютере с Windows

Эта процедура переносит тот же MCP `electronics-parts` на другой компьютер без копирования API-ключей.

### 1. Перенесите файлы

1. Установите OpenCode на целевом компьютере.
2. Установите Node.js версии 20 или новее (стандартный путь — `C:\Program Files\nodejs\node.exe`) и убедитесь, что команды `node` и `npm` доступны в PowerShell.
3. Клонируйте репозиторий либо перенесите только `mcp/electronics-parts/server.mjs`, `package.json` и `package-lock.json`. Не копируйте `node_modules`, API-ключи или целый профиль пользователя.

### 2. Создайте каталог MCP

На целевом компьютере запустите:

```powershell
$serverDir = Join-Path $HOME ".config\opencode\mcp\electronics-parts"
New-Item -ItemType Directory -Force -Path $serverDir
```

Скопируйте переданные `server.mjs`, `package.json` и `package-lock.json` в `$serverDir`.

### 3. Установите зависимости Node.js

В каталоге MCP на целевом компьютере выполните:

```powershell
Set-Location $serverDir
npm install
```

`package.json` уже содержит требуемые зависимости (`@modelcontextprotocol/sdk@^1.30.0`, `zod@^4.4.3`); `package-lock.json` фиксирует точные версии.

### 4. Подключите MCP в OpenCode

Откройте глобальную конфигурацию на целевом компьютере:

```text
%USERPROFILE%\.config\opencode\opencode.jsonc
```

Если в файле уже есть объект `mcp`, добавьте только запись `electronics-parts`. Не заменяйте существующих провайдеров, MCP-серверы и другие настройки.

Замените `C:\Users\YOUR_WINDOWS_USER` на настоящий абсолютный путь целевого компьютера. **Обязательно укажите абсолютный путь к `node.exe`**: приложение OpenCode не ищет `node` в PATH и падает с `uv_spawn 'node' ENOENT`, если в `command` стоит просто `"node"`.

```jsonc
{
  "mcp": {
    "electronics-parts": {
      "type": "local",
      "command": [
        "C:\\Program Files\\nodejs\\node.exe",
        "C:\\Users\\YOUR_WINDOWS_USER\\.config\\opencode\\mcp\\electronics-parts\\server.mjs"
      ],
      "cwd": "C:\\Users\\YOUR_WINDOWS_USER\\.config\\opencode\\mcp\\electronics-parts",
      "environment": {
        "DIGIKEY_CLIENT_ID": "{env:DIGIKEY_CLIENT_ID}",
        "DIGIKEY_CLIENT_SECRET": "{env:DIGIKEY_CLIENT_SECRET}",
        "MOUSER_API_KEY": "{env:MOUSER_API_KEY}",
        "LCSC_API_KEY": "{env:LCSC_API_KEY}",
        "LCSC_API_SECRET": "{env:LCSC_API_SECRET}",
        "JLCPCB_APP_ID": "{env:JLCPCB_APP_ID}",
        "JLCPCB_ACCESS_KEY": "{env:JLCPCB_ACCESS_KEY}",
        "JLCPCB_SECRET_KEY": "{env:JLCPCB_SECRET_KEY}",
        "ELITAN_COOKIE": "{env:ELITAN_COOKIE}"
      },
      "enabled": true,
      "timeout": 30000
    }
  }
}
```

Если проект синхронизируется между компьютерами, проверьте, что проектный `opencode.jsonc` не содержит пути другой машины: `command` и `cwd` всегда должны указывать на локальное расположение `server.mjs`.

### 5. Добавьте ключи локально

На целевом компьютере задайте API-переменные из раздела [Добавление ключей API в Windows](#добавление-ключей-api-в-windows). Для LCSC и JLCPCB каждому компьютеру могут понадобиться собственное одобрение доступа и whitelist IP-адреса.

### 6. Перезапустите и проверьте

Полностью закройте и заново запустите OpenCode, затем выполните:

```powershell
opencode.cmd mcp list
```

Ожидаемый результат:

```text
electronics-parts  connected
```

Проверьте работу в OpenCode простым запросом:

```text
Найди резисторы 10 кОм 0603 с допуском 1% на DigiKey и Mouser.
```

### Обновление на другом компьютере

Замените `server.mjs` актуальной версией с исходного компьютера, оставьте локальные переменные с ключами без изменений и перезапустите OpenCode. Повторно выполните `npm install` только при изменении требуемых версий зависимостей в `package.json`.
