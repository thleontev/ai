# Как прогонять acceptance tests

## Ручной режим

1. Запустить OpenCode с обоими MCP.
2. Для каждого case из `test-cases.yaml` отправить `prompt`.
3. Если указан fixture, использовать его как stub/mock данные либо сверить логику на реальном ответе аналогичной структуры.
4. Проверить все условия `must`.
5. Любое нарушение stop-ship правила из `TEST_PLAN.md` = FAIL.

## Автоматизация позже

После стабилизации MCP добавить test harness, который:
- поднимает SQLite MCP на временной БД;
- подменяет supplier layer fixtures;
- запускает агента/модель с фиксированной конфигурацией;
- проверяет структурированный JSON-result, а не формулировки естественного языка.

Сначала следует стабилизировать контракты инструментов и skill workflow, а затем автоматизировать LLM evals.
