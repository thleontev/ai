# Electronics Parts

Локальный набор MCP-инструментов и OpenCode skills для инженера, который подбирает компоненты, проверяет BOM и готовит закупку. Дайте MPN или спецификацию платы — проект соберёт предложения поставщиков, посчитает нужное количество с MOQ и ценовыми ступенями, а для замены отделит гипотезу от подтверждённых данными фактов.

## Что можно сделать

1. Найти конкретный компонент по MPN у международных и российских поставщиков: цена, наличие, MOQ, срок и ссылка на карточку.
2. Проверить BOM под заданный тираж: какие позиции доступны, где дефицит и что требует решения.
3. Составить план закупки по строкам BOM с учётом количества, кратности заказа, ценовых уровней и сроков.
4. Исследовать замену компонента: сравнить электрические параметры, корпус, pinout и посадочное место с привязкой к даташитам и другим источникам.

## Источники данных

| Источник | Какие данные можно получить | Условие доступа |
| --- | --- | --- |
| DigiKey | Каталог, параметрический поиск, цены, наличие, даташиты | DigiKey API |
| Mouser | Поиск по MPN и ключевым словам, цены, наличие, даташиты | Mouser API |
| LCSC | Поиск, наличие и ценовые уровни | LCSC B2B API |
| LCSC (публичный поиск) | Точный MPN/C-код, цены, остатки, даташит; выдача сайта | WEB поиск |
| JLCPCB | Наличие для PCBA, цены и характеристики по LCSC C-коду | JLCPCB API |
| <br>• ЧипДип<br>• Промэлектроника<br>• Березка (Берелком)<br>• ДКО Электронщик<br>• Платан<br>• Элитан | Поиск, наличие и ценовые уровни (публичный поиск) | WEB поиск |

Оперативные цены и остатки требуют перепроверки перед заказом.

## Для чего это полезно

Вместо ручного поиска в нескольких каталогах и таблицы без истории решений вы получаете единый воспроизводимый процесс. Предложения и исследования можно сохранить локально в SQLite, а вывод о прямой замене не появится без проверенной матрицы совместимости.

Проект работает локально: ключи API остаются у вас, рабочая БД не публикуется, а данные поставщиков запрашиваются только по необходимости.

## Как устроено

```text
User -> OpenCode Agent -> Skill -> electronics-parts MCP
                              \-> sqlite-memory MCP -> SQLite
```

- **Agent** понимает запрос, выбирает skill, рассуждает и формирует ответ.
- **Skill** задает детерминированный workflow и правила качества.
- **electronics-parts MCP** получает свежие данные поставщиков и параметрического поиска.
- **sqlite-memory MCP** хранит проекты, BOM, снимки предложений, результаты и append-only исследования замен с контекстом применения и доказательствами.
- **SQLite** — единственная долговременная память сервиса.

Проект работает локально, без RAG/vector DB, очередей, микросервисов, multi-agent и отдельного web-backend.

## Структура

- `.opencode/skills/*` — 4 готовых OpenCode skill.
- `mcp/electronics-parts/` — локальный stdio MCP для поиска у поставщиков.
- `mcp/sqlite-memory/` — SQLite MCP server для предметной памяти.
- `tests/fixtures/` — тестовые BOM.

## Быстрый старт

Требование: Node.js 20 или новее.

1. Клонировать репозиторий и установить зависимости:
   ```bash
   git clone <REPOSITORY_URL>
   cd electronics-parts
   npm ci --prefix mcp/electronics-parts
   npm ci --prefix mcp/sqlite-memory
   ```
2. Скопировать `.opencode/skills` в корень проекта OpenCode.
3. Создать БД:
   ```bash
   mkdir data
   sqlite3 data/electronics-parts.db ".read db/schema.sql"
   ```
4. Добавить оба MCP из `mcp/electronics-parts/` и `mcp/sqlite-memory/` в `opencode.jsonc`. Шаблон приведён в `mcp/sqlite-memory/opencode.example.jsonc`.
5. Задать только нужные API-переменные из `.env.example`; значения не добавлять в конфигурацию и Git.
6. Перезапустить OpenCode.
7. Выполнить проверку:
   ```bash
   npm run check
   npm test
   ```
8. Прогнать сценарии из `tests/test-cases.yaml`.

## Публикация и безопасность

- В репозиторий входят исходники, навыки, схема БД и тестовые fixtures. Рабочая SQLite-БД и `node_modules` исключены.
- Необходимые переменные окружения перечислены в `.env.example`. Никогда не коммитьте ключи API, секреты OAuth или `ELITAN_COOKIE`.
- Официальные API используются только согласно условиям поставщиков. Интеграции с публичными страницами требуют письменного разрешения на автоматизированный доступ; подробности — в [SECURITY.md](SECURITY.md).

## Важное правило замены

LLM может предложить кандидата замены, но значение электрического параметра, pinout, package и вывод о drop-in совместимости не считаются проверенными, пока они не подтверждены источником данных/даташитом. Непроверенные факты маркируются `UNVERIFIED`; `EXACT_DROP_IN` / `QUALIFIED_DROP_IN` дополнительно защищены в SQLite MCP от сохранения без проверенной матрицы совместимости.
