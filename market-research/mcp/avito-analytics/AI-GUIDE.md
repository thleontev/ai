# Avito «Аналитика спроса» — инструкция для ИИ-агентов

MCP-сервер `avito-analytics` предоставляет доступ к данным раздела «Аналитика спроса» Авито
(спрос в категориях + частотность поисковых запросов) через авторизованную сессию браузера.
Полное описание API и устройства раздела — в `ARCHITECTURE.md`.

## 1. Обязательный порядок работы

Сессия не существует, пока не открыта. Никакие инструменты, кроме `avito_session_*`,
не работают до открытия браузера.

```
1. avito_session_open (wait_login=true)   — открыть браузер; при необходимости пользователь залогинится вручную
2. avito_session_status                    — убедиться, что authorized=true
3. сбор данных: avito_market / avito_wordstat / avito_location (паузы сервер ставит сам)
4. avito_session_close                     — опционально, по завершении работы
```

Если `avito_session_open` завершился с ошибкой «Login timeout» — значит пользователь не
успел авторизоваться. Сообщите ему, что нужно войти в открывшемся окне браузера,
и повторите вызов (профиль persistent, cookies сохраняются между запусками).

Если `authorized=false` в статусе — данные недоступны, запросы делать нельзя.

## 2. Инструменты

### Управление сессией

| Инструмент | Параметры | Назначение |
|---|---|---|
| `avito_session_open` | `wait_login` (bool, по умолч. true), `timeout_ms` | Открыть браузер на /analytics и дождаться авторизации |
| `avito_session_status` | — | Состояние: браузер, авторизация, лимит запросов, кулдауны |
| `avito_session_close` | — | Закрыть браузер (сессия сохраняется на диске) |

### Данные

| Инструмент | Параметры | Ответ |
|---|---|---|
| `avito_market` | `node_id` (null = все категории), `location_ids` (обязательно, ≥1), `district_ids`, `metro_ids`, `dynamic_filters`, `group` (`day`\|`month`), `order` (`name`\|`demand`\|`contacts`\|`views`\|`sellers`\|`items`), `direction` (`asc`\|`desc`), `split_by` (`category`\|`district`\|`metro`) | `nodes[]` (nodeName, countSellers, countItems, views, contacts, demand.value/estimate), `config`, `breadcrumbs`, при детализации — `summary` |
| `avito_wordstat` | `queries` (1–10 фраз), `duration` (`week`\|`month`), `location_id`, `category_id`, `strict_mode` | `periodData[]`: `{date, counts[]}` — по одному count на фразу на дату; `total_requests` — сумма |
| `avito_location` | — | `{id, name}` текущего региона |
| `avito_location_search` | `query` (город/регион), `limit` (1–20, по умолч. 10) | Подсказки локаций с id через публичный suggest (`/web/1/slocations`): `locations[]` с полем `exact` (точное совпадение имени). Кэш на диске 30 дней, бюджет запросов не тратит. Берите `id` у записи с `exact:true` и передавайте в `location_id` / `location_ids` |
| `avito_microcat_suggest` | `query` | Подсказки микрокатегорий для `dynamic_filters` |

Каждый успешный ответ содержит поле `archived` — путь к сохранённому сырому JSON. Сохраняйте его как ссылку на evidence; не включайте сам архив в публичный отчёт или пакет skill.

## 3. Лимиты и паузы (настроены сервером, не отключаются)

- Между запросами сервер сам ждёт **случайные 8–20 сек** — не нужно добавлять свои sleep, но и не вызывайте инструменты в цикле быстрее, чем сервер успевает.
- **≤50 запросов на серию**, затем пауза до конца кулдауна (30 мин). Ошибка лимита — сигнал завершить сбор.
- При 403/429/HTML-ответе (капча) сервер ставит **автопаузу на 24 ч** (`blocked_until` в статусе) — все последующие вызовы будут отклонены. В этом случае остановитесь, сообщите пользователю и не пытайтесь обойти.

## 4. Рекомендуемые сценарии

### Обзор спроса в регионе (минимальный, 1 запрос)

```
avito_market { node_id: null, location_ids: [660630], group: "month", order: "demand", direction: "desc" }
```

### Детализация категории (по 1 запросу на категорию)

```
1. avito_market { node_id: null, location_ids: [...] }          → все категории верхнего уровня
2. avito_market { node_id: 7, location_ids: [...] }             → подкатегории «Электроника» + summary
3. при необходимости — node_id подкатегории (nodeId из ответа)  → вложенность дальше
```

В ответе `config.splitBy.options` показывает доступные разрезы (`category` = «По подкатегориям»).

### Сравнение поисковых запросов (1 запрос)

```
avito_wordstat { queries: ["телефон", "айфон"], duration: "month", location_id: 660630, category_id: 7 }
```

`counts` на дату = [число по «телефон», число по «айфон»] — порядок соответствует `queries`.

### Массовый сбор

- По одному региону за серию: 1 (обзор) + N (подкатегории) ≤ 15 запросов.
- Регион → все топ-категории: до 50 запросов (весь бюджет серии), после — перерыв.
- Не перебирайте все регионы подряд в одной сессии: максимум 3–5 регионов, между ними длительные перерывы.

## 5. Интерпретация данных

- `demand.value` — уровень спроса 1–3; `demand.estimate` — оценочный показатель.
- `summary.viewsPerItem`, `summary.viewsToContactConversion` — только при детализации (node_id задан).
- Категории с <5 продавцами скрыты (`config.minSellersCount`); скрытые узлы — `config.forbiddenNodes`, `config.hiddenFields`.
- Периоды: `group: "day"` = вчера; `group: "month"` = прошлый месяц; `duration: "week"` = 7 последних дней.
- Сумма `counts` в wordstat = «Всего запросов» на странице Авито.

## 6. Обработка ошибок

| Ситуация | Действие |
|---|---|
| «Login timeout» | Попросить пользователя авторизоваться в открытом окне, повторить `avito_session_open` |
| «Daily session limit reached» | Сбор завершён на сегодня; подождать кулдаун (30 мин) или отложить |
| «Session is paused… 24h» | Капча/блок; прекратить сбор, предупредить пользователя |
| «Could not launch a browser» | Сообщить пользователю (нет Chrome/Edge или профиль занят) |
| Ошибка HTTP в ответе инструмента | Проверить `blocked_until` в статусе; если нет блока — повторить через ≥1 мин, 1 раз |

## 7. Ограничения сервера

- Запросы строго последовательны (внутренняя блокировка) — параллельных вызовов не будет.
- fetch выполняется из контекста открытой вкладки: вкладка всегда на www.avito.ru, сервер сам возвращает её на /analytics при необходимости.
- Браузер headful по умолчанию (нужен для логина); `AVITO_HEADLESS=true` — только для уже авторизованного профиля.
- Профиль один на сервер (по умолчанию `%LOCALAPPDATA%\OpenCode\avito-analytics\profile`); не запускайте два экземпляра сервера одновременно — будет конфликт профиля. Не задавайте `AVITO_DATA_DIR` внутри Synology Drive, Git-репозитория или общей папки.
