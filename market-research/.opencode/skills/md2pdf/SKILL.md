# md2pdf: Markdown → PDF

Пайплайн конвертации, проверенный на Windows (PowerShell 5.1, Edge headless).

```
report.md  →  report.html (CSS-шаблон)  →  report.pdf (Playwright print)  →  pdf-check/page-*.png + текст-проверка
```

## Требования (проверить один раз, при отсутствии — установить)

- Python + библиотеки: `python -m pip install markdown pymupdf --disable-pip-version-check`
  (если установка висит — повторить с `--timeout 20`; pymupdf — большой, качается медленно).
- Node.js + playwright-core в общем кэше:
  `npm install playwright-core --prefix "$env:LOCALAPPDATA\opencode\md2pdf" --no-fund --no-audit`
- Браузер: Edge или Chrome (автодетект в `print_pdf.js`; можно задать путь через переменную окружения `CHROME_EXE`).

Проверка окружения:
```powershell
python -c "import markdown, pymupdf; print('py ok')"
node -e "require('playwright-core'); console.log('pw ok')"   # с NODE_PATH (см. ниже)
```

## Шаги конвертации

Скрипты лежат в `scripts/` этой папки скилла. Запускать из любой директории, пути передавать как аргументы.

```powershell
# 1. Markdown → HTML по шаблону с CSS (A4, стили таблиц, колонтитулы)
python .opencode/skills/md2pdf/scripts/build_html.py report.md report.html

# 2. HTML → PDF через Playwright (headless Edge, печать A4)
$env:NODE_PATH = "$env:LOCALAPPDATA\opencode\md2pdf\node_modules"
node .opencode/skills/md2pdf/scripts/print_pdf.js report.html report.pdf "Текст нижнего колонтитула · дата"

# 3. PDF → PNG страниц + извлечение текста и проверка ключевых фраз
python .opencode/skills/md2pdf/scripts/render_png.py report.pdf pdf-check [phrases.txt]
```

Параметры скриптов:
- `build_html.py <input.md> <output.html>` — на выходе HTML с тем же именем; `<title>` берётся из первого заголовка. Выводит `OK tables: N`, `WARN table separator line N: ...` для неверного числа колонок, `WARN block boundary line N: ...`, если перед таблицей или списком после абзаца нет пустой строки, и `WARN nested list line N: ...`, если вложенный пункт отступлен не кратно четырём пробелам. Такие блоки python-markdown может оставить сырым текстом в `<p>` или сделать плоским списком.
- `print_pdf.js <source.html|url> <output.pdf> [footer-text]` — принимает и `file://`, и `http(s)://`; HTTP-сервер не нужен.
- `render_png.py <input.pdf> <outdir> [expected-phrases.txt]` — PNG по 130 dpi; `expected-phrases.txt` — UTF-8, по фразе на строку (важно: фразы с дефисами/диапазонами типа «10–20» искать в извлечённом тексте; переносы строк в ячейках таблиц нормализуются пробелами).

## Графики (SVG)

- Вставка в MD: `![Подпись](charts/xxx.svg)` — путь относительный от отчёта (HTML лежит рядом с MD, папка `charts/` — рядом с отчётом). CSS шаблона содержит `img { max-width: 100% }`, SVG масштабируется под A4.
- Генерация: чистый python без зависимостей (простой текстовый генератор SVG). Обязательно `width`/`height` + `viewBox`; шрифты системные (`Arial, Segoe UI, sans-serif`) — кириллица печатается корректно. В PDF SVG рендерится как вектор (размер PDF почти не растёт).
- Типичные ошибки (проверены на практике, проверяйте перед печатью):
  - легенда и заголовок/подзаголовок на одной y-координате — текст перекрывается;
  - `ymax` шкалы меньше максимального значения ряда — бар выходит за границы графика и перекрывает соседний текст;
  - подписи категорий длиннее ширины группы/столбца — наезжают на соседние;
  - подписи значений справа от бара не влезают в ширину холста.
- Проверка, что SVG попали в PDF (страницы с графиками — векторные drawings):
  `python -c "import pymupdf; d=pymupdf.open('report.pdf'); print([len(p.get_drawings()) for p in d])"`
  страницы с графиками/таблицами имеют сотни drawings; график без содержимого = 0.

## Верификация (обязательный шаг)

1. `build_html.py` не должен выводить ни одного `WARN`. Для `WARN table separator` исправь число сегментов `|...|`; для `WARN block boundary` добавь пустую строку перед таблицей или списком; для `WARN nested list` используй ровно четыре пробела на каждый уровень вложенности. Затем пересобери HTML. `OK tables: N` должно быть ≥ числа таблиц в отчёте (в крайнем случае — сверять ключевые таблицы в HTML по `<table>`).
2. Прочитать `<outdir>/_check.txt` — там `фраза -> True/False` по каждой ключевой фразе и первые 600 символов извлечённого текста. Все ключевые фразы отчёта должны быть True (включая цифры, URL, имена компаний).
3. `pdf-check/page-*.png` — рендеры страниц для визуальной проверки пользователем. ВАЖНО: модель может не поддерживать чтение изображений — тогда визуальную проверку делает пользователь, а агент полагается на текст-проверку.
4. Проверить количество страниц и что PNG созданы (не нулевые файлы). При наличии SVG-графиков — проверить drawings (см. выше).

## Ограничения и примечания

- Консоль PowerShell 5.1 выводит кириллицу в cp866 — НЕ судить об успехе по виду консоли; результат читать из `_check.txt` (UTF-8). Скрипты намеренно пишут в stdout только ASCII-статусы.
- Таблица, не распознанная парсером, остаётся текстом в `<p>` — в PDF выглядит как слитные строки, а не «отсутствует». Симптом: в HTML нет `<td>` с ожидаемым содержимым при том, что `Contains` по строке срабатывает (текст есть, но не как таблица).
- Не использовать MCP-playwright для печати: `page.pdf()` работает только в headless; для печати применяется `playwright-core` + системный Edge/Chrome напрямую.
- Эмодзи (✅/⚠️/❌) в Edge печатаются корректно; при проблемах можно заменить их в HTML на +/−.
- Если в HTML нет `<meta charset="utf-8">`, кириллица в PDF сломается — шаблон скрипта уже содержит.
- Временные файлы (`_check.txt`, `pdf-check/`) после подтверждения пользователем можно удалить, но сам PDF и HTML оставить рядом с MD.

## Переиспользование

Скрипты параметризованы: один и тот же скилл конвертирует любой отчёт в любом проекте. Для глобальной доступности во всех проектах скопируйте папку скилла в `~/.config/opencode/skills/md2pdf/`.
